1. Dos orígenes

Cada fuente vive en generate.icons/fonts/<fuente>/ y registra en su icons.config.mjs de dónde salen sus iconos (campo origin):

originCuándoCómo se llena source/Generar
'figma' Los iconos están en un archivo de Figma. npm run pull -- <fuente> lee el nodo de Figma (necesita token). npm run build -- <fuente>
'local' Te comparten los SVG (sueltos o en carpetas). Copias los SVG a mano en source/. 
origin 'figma':  Figma ──── npm run pull ───▶ source/ ── npm run build ──▶ dist/ + icons.json
origin 'local':  SVG ────── copiar a mano ──▶ source/ ── npm run build ──▶ dist/ + icons.json

2. Con Claude Code: /generar-fuente

El skill está en generate.icons/.claude/skills/generar-fuente/. Invócalo con /generar-fuente o en lenguaje natural: “regenera incontrol-icons”, “crea una fuente nueva desde Figma”, “ya copié los SVG en source de shared-icons, genérala”.

  1. Pregunta si es una fuente existente (lista las fuentes con su origen) o nueva.
  2. Si es nueva, pregunta el origen: Figma (URL del frame de iconos, nombre, prefijo y filtro de capas, p. ej. icon-) o carpeta local (nombre y prefijo), y la crea con npm run new.
  3. Figma: ejecuta la simulación (npm run pull -- <fuente> --dry-run), te resume categorías, renombrados, añadidos y eliminados, extrae y genera. Local: revisa source/ (o copia ahí la carpeta que le indiques) y genera.
  4. Te informa del total de iconos, los cambios, los avisos y dónde ver la vista previa, y te ofrece llevarla al proyecto con /exportar-fuente.
El skill aparece en las sesiones de Claude Code abiertas en generate.icons/. Sin Claude, los comandos de las secciones 3 y 4 hacen lo mismo.

3. Origen Figma

Crear la fuente

cd generate.icons
npm run new -- incontrol-system --figma "https://www.figma.com/design/<file>/<nombre>?node-id=12-34" --prefix sys --filter sys-
  • --figma: enlace al frame o sección de iconos, con node-id (en Figma: Copy link to selection).
  • --filter: solo las capas cuyo nombre empieza por ese texto son iconos (opcional; sin él, todos los componentes).
  • Los grupos hijos del nodo son las categorías; los iconos sueltos, sin categoría.

Extraer y generar

npm run pull -- incontrol-system --dry-run   # resumen, no escribe nada
npm run pull -- incontrol-system             # source/ = lo que hay en Figma
npm run build -- incontrol-system

Necesita el token de Figma: Conectar con Figma. Las categorías y los iconos salen en el orden del lienzo de Figma.

4. Origen local (carpeta de SVG)

Crear la fuente

npm run new -- shared-icons --local --prefix icon

Copiar los SVG

Copia lo que te compartieron en generate.icons/fonts/shared-icons/source/, tal como venga:

source/
├── Navigation/            # carpeta = categoría
│   ├── Arrow Left.svg     # → icon-arrow-left
│   └── icon-nav-up.svg    # → icon-nav-up
├── Business & finance/    # → categoría "Business & finance"
│   └── bank.svg           # → icon-bank
└── logo.svg               # suelto = sin categoría → icon-logo
  • Con categorías: una carpeta por categoría (un solo nivel, sin subcarpetas).
  • Sin categorías: todos los SVG directamente en source/.
  • Se pueden mezclar las dos formas.
  • No hace falta renombrar nada: los nombres se normalizan al generar.

Generar

npm run build -- shared-icons

El build valida source/ antes de escribir nada y genera dist/ e icons.json. Las categorías y los iconos salen en orden alfabético. npm run pull no aplica a una fuente local.

Una fuente solo dibuja rellenos: si un SVG usa trazos (stroke), el build avisa y en la fuente saldría vacío. Pide a quien lo compartió el SVG con los trazos convertidos a relleno (en Figma: Outline stroke + Flatten).

6. Duplicados

Dos iconos no pueden acabar con el mismo nombre, aunque estén en categorías distintas. Si pasa (por ejemplo Add Item.svg y add_item.svg, o dos capas de Figma iguales), no se genera nada y se listan las rutas: renombra o borra uno (en Figma o en source/) y vuelve a generar. Lo mismo con dos carpetas que dan la misma categoría (Business & finance y business-and-finance).

7. Iconos eliminados (trash/)

Lo que ya no está en Figma, o el SVG que borras de source/, no se genera. Queda registrado en fonts/<fuente>/trash/:

  • trash/trash.json: nombre, categoría, código Unicode y fecha de cada icono eliminado.
  • Origen Figma: también se guarda su SVG (trash/<categoría>/<icono>.svg). Origen local: solo la entrada, porque el SVG lo borraste tú.
  • Su código queda reservado: ningún icono nuevo lo reutiliza.
  • Si el icono vuelve (a Figma o a source/) con el mismo nombre, recupera su código y sale de trash/.
  • trash/ no forma parte de la fuente: no sale en dist/, en icons.json ni al exportar.
  • Para olvidar un icono del todo (y liberar su código), borra su entrada de trash.json y su SVG.

8. Qué se genera

fonts/<fuente>/
├── source/              # los SVG (de Figma o copiados)
├── dist/                # GENERADO: <fuente>.css, .woff2, .woff, .ttf, .eot, .svg, .html, .json
├── icons.json           # GENERADO: categorías → iconos, con su código
└── trash/               # iconos eliminados (si los hay)

Revisa dist/<fuente>.html en el navegador (vista previa con buscador) y llévala al proyecto con Exportar fuente. Los códigos Unicode se conservan por nombre entre generaciones.

9. Mensajes de error

MensajeCausaSolución
… is duplicated Dos SVG o capas dan el mismo nombre de icono. Renombra o borra uno y vuelve a generar.
Folders "…" and "…" are the same category Dos carpetas de source/ dan la misma categoría. Une sus SVG en una sola carpeta.
… nested folders are not allowed inside a category Subcarpetas dentro de una categoría. Deja un solo nivel de carpetas.
No SVGs found in … source/ está vacío. Copia los SVG (local) o ejecuta npm run pull (Figma).
… is a local font (origin: 'local') npm run pull sobre una fuente local. Usa npm run build -- <fuente>.
… has no Figma URL Fuente de Figma sin figma registrado. Regístralo en icons.config.mjs, o pon origin: 'local' si sus SVG se copian a mano.
Missing FIGMA_TOKEN / 403 / 404 Problemas con el token o el acceso al archivo de Figma. Ver Conectar con Figma → Mensajes de error.
